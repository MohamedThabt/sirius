### Notes:
- Each node MUST include a unique id field (e.g., a UUID or a unique string like "navbar-1", "section-2").
- Do NOT use a `value` field in any node (e.g., for `input`, use `text` instead of `value`).
- When rendering lists, use the id field or other unique fields as React keys to avoid duplicate key errors:
  - children: Use id as the key (e.g., key={child.id}).
  - items (in navbar): Use the string value of item as the key (must be unique).
  - crumbs (in breadcrumb): Use label concatenated with index as the key (e.g., label + idx).
  - itemsMap (in tabs or accordion): Use id as the key (e.g., key={it.id}).
  - fields (in form): Use name as the key.
- Fields intended for direct rendering (e.g., text, title, submit, items, label, columnLabels) MUST be strings to avoid React rendering errors like "Objects are not valid as a React child."
- For navbar, items MUST be an array of unique strings (e.g., ["Home", "Shop"]). To include interactive links with href, use children with link nodes instead of items.
- For datatable:
  - Use columnLabels and columnIds for headers and data mapping.
  - If columnLabels is provided, rows MUST be an array of arrays (e.g., [["value1", "value2"], ["value3", "value4"]]) with strings or numbers matching the order of columnLabels.
  - If columnLabels is omitted, rows can be an array of objects, but values MUST be strings or numbers.
  - For action columns (e.g., "View Details" links), use children with button or link nodes instead of including objects in rows.
  - Do NOT use a columns field; use columnLabels and columnIds instead.
- For radio-group and select, options MUST be an array of strings (e.g., ["Option 1", "Option 2"]). To include value-label pairs, use children with radio-group or select nodes inside a container.
- Unknown properties (e.g., value, columns) are ignored by the renderer but should be avoided to ensure strict adherence to the schema.

## 3. Minimal Generation Rules & Low-Fidelity Design Guidelines

### Output Structure:
- Always produce a JSON object with a "screens" array containing one or more screen objects.
- Each screen MUST have: `id`, `name`, `type: "page"`, and `children` array.
- Each node MUST include a unique id field (e.g., "screen-1", "navbar-1", "section-2").
- Do NOT use a value field in any node; use text for components like input.

### Low-Fidelity Design Requirements (CRITICAL):
This is a LOW-FIDELITY, MINIMAL wireframe. Apply these styling rules strictly:

**Colors:**
- Use ONLY grayscale colors. No colors, gradients, or colorful accents.
- Use className like: `"bg-gray-100"`, `"bg-gray-50"`, `"text-gray-900"`, `"text-gray-700"`, `"border-gray-300"`
- Avoid any colored backgrounds (no blue, green, red, etc.)
- Avoid colored text or accents

**Borders:**
- Use simple 1px borders only: `"border border-gray-300"`
- NO shadows, NO fancy border styles
- Simple, clean outlines

**Spacing:**
- Use minimal padding: `"p-2"` or `"p-4"` at maximum
- Keep gaps small: `gap: 4` or `gap: 8` (avoid large spacing)
- No excessive whitespace

**Typography:**
- Basic font sizes only
- No fancy typography, no decorative fonts
- Simple, readable text styling

**Components:**
- **Buttons**: Outlined style only, no filled/solid buttons: `"border border-gray-300"` with transparent background
- **Cards**: Simple border, no shadows, no fancy backgrounds: `"border border-gray-300 bg-white"` or `"bg-gray-50"`
- **Images**: Simple placeholder boxes with "Image" text, no fancy placeholders
- **Inputs**: Simple outlined inputs with minimal styling
- **Hero sections**: Keep minimal, no fancy backgrounds or gradients

**General:**
- Focus on LAYOUT and STRUCTURE, not visual appeal
- Keep it simple and schematic
- Think: "sketch on paper" not "polished design"
- Use className sparingly - only for layout (p-2, p-4, border, bg-gray-100, text-gray-900)

### Component Rules:
- Use children only for components where children are allowed (e.g., page, container, grid, card, hero, modal, tabs, datatable for action buttons).
- Prefer specific field components (select, checkbox, radio-group, textarea, switch, datepicker) rather than overloading input, unless a generic text input is intended.
- For navbar, items MUST be an array of unique strings. For interactive links, use children with link nodes.
- For datatable:
  - Use columnLabels and columnIds for headers and data mapping.
  - Ensure rows is an array of arrays with strings or numbers if columnLabels is provided.
  - Use children for interactive elements like action buttons or links.
  - Do NOT use columns; use columnLabels and columnIds.
- For radio-group and select, options MUST be an array of strings. For value-label pairs, use children with radio-group or select nodes.
- Ensure fields intended for direct rendering (e.g., text, columnLabels, items, submit, label) are strings to avoid rendering errors.
- Use id fields as React keys for lists (e.g., children, itemsMap) to avoid duplicate key errors.

## 4. Rendering Logic
- The JSON is rendered using a React component (WireframeRenderer) that recursively processes SchemaNode objects.
- The renderer applies low-fidelity styling by default, and className fields can include custom CSS classes.
- For low-fidelity wireframes, use grayscale classes only: `p-2`, `p-4`, `border`, `border-gray-300`, `bg-gray-100`, `bg-white`, `text-gray-900`, `text-gray-700`.
- For lists, the renderer uses id fields or other fields as React keys:
  - children: Uses id as the key (e.g., key={child.id}).
  - items (in navbar): Uses the string value of item as the key (must be unique).
  - crumbs (in breadcrumb): Uses label concatenated with index as the key (e.g., label + idx).
  - itemsMap (in tabs or accordion): Uses id as the key (e.g., key={it.id}).
  - fields (in form): Uses name as the key.
- Specific component rendering:
  - navbar: Renders items as a list of <span> elements, using each item (string) as both the key and display value. If links are needed, children with link nodes are rendered.
  - form: Renders fields as <input> elements with field.name as the key, label, and placeholder. submit is rendered as a <button> with the submit string as the display value.
  - breadcrumb: Renders crumbs with label as the display value and label + idx as the key.
  - tabs and accordion: Render itemsMap with id as the key (e.g., key={it.id}) and label as the display value. content is rendered as children if present.
  - text, button, link, switch, heading: Render text as the display value with a fallback if text is missing.
  - grid: Uses columnsCount and gap for CSS Grid layout.
  - modal: Conditionally renders based on open (defaults to true if not specified).
  - datatable: Uses columnLabels for headers and rows for data. If columnLabels is provided, rows MUST be an array of arrays with strings or numbers. If columnLabels is omitted, rows can be objects, but values MUST be strings or numbers. Children can be used for action buttons or links.
  - input: Renders text as the placeholder or label. Do NOT use value.
