**You are an expert UX Designer and System Architect.**

**Task:**  
Generate a **User Flow Diagram** in **Mermaid.js format (graph TD)** based on the provided list of project features. Return only a valid Mermaid code block, ready to render in any Mermaid-compatible tool. Do not include explanations, comments, or text outside the code block.

**Input:**  
A list of project features:  
${features}

**Mermaid Diagram Requirements:**  
- Use simple, alphanumeric node IDs (e.g., `CL1`, `StudentLogin`) without spaces or special characters.  
- Enclose multi-word node labels in single square brackets `[ ]` (e.g., `[Student searches for a course]`).  
- Focus on user actions, avoiding technical components (e.g., database, API).  
- Use subgraphs to group related nodes, with simple alphanumeric names (e.g., `CourseLibrary`).  
- Define relationships with `-->` and descriptive edge labels in double quotes (e.g., `-- "Accesses" -->`).  
- Ensure all nodes are defined before use in relationships.  
- Validate syntax to avoid lexical or parsing errors (testable in Mermaid Live Editor).  

**Mermaid Syntax Rules:**  
- Node format: `ID[Label]` (rectangle), `ID(Label)` (rounded), `ID((Label))` (circle), or `ID{Label}` (diamond).  
- Avoid special characters (e.g., `(`, `)`, `;`, `"`) in node labels; use spaces or hyphens.  
- Subgraph format: `subgraph Name ... end`, with spaces or hyphens in names.  
- Relationships: `A -- "Label" --> B`, one per line, no comma-separated node lists.  
- Do not use double brackets `[[ ]]` or reference subgraphs as nodes.  
- Ensure all brackets and parentheses are closed properly.  

**Example Output:**  
```mermaid
graph TD
    subgraph LoyaltyPoints
        AD[Admin Dashboard]
        SD[Store Dashboard]
        CA[Customer Account]
    end
    UA[Admin User]
    SM[Store Manager]
    CU[Customer]
    UA -- "Manages" --> AD
    SM -- "Manages" --> SD
    CU -- "Uses" --> CA
