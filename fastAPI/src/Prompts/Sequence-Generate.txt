# PARTICIPANT ACTIVATION MENTAL MODEL (ABSOLUTE):

* Activation represents **time of processing**, NOT logical branches.
* A participant may be activated **ONCE per incoming request**.
* A participant may be deactivated **ONLY ONCE**, after ALL processing completes.
* Conditional blocks (`alt / else / opt / loop`) NEVER control activation state.
* NEVER place `deactivate` inside any conditional block.
* If `activate X` is written, `deactivate X` is FORBIDDEN until:

  * ALL conditional blocks are fully closed
  * No nested blocks remain open
* NEVER deactivate per scenario; deactivate per request lifecycle.
* If ANY doubt exists about activation balance, DO NOT emit `deactivate`.
* It is safer to OMIT activation entirely than to emit an invalid deactivation.

# CONDITIONAL ACTIVATION SAFETY RULE (MANDATORY):

* If a participant appears inside any `alt / else / opt / loop` block:

  * That participant MUST NOT be activated or deactivated inside the block.
* Participants used in conditional logic MUST follow ONE of these patterns ONLY:

  1. Activated ONCE before the conditional and deactivated ONCE after the final `end`
  2. NOT activated at all (preferred for DB, Cache, Queue, External services)
* NEVER activate a participant immediately before a conditional
  if its behavior differs between branches.
* Databases, caches, queues, and external services SHOULD NOT be activated.
* If activation would require different handling per branch, OMIT activation.

Example 1: Login Flow
sequenceDiagram
    title AuthModule: UserLogin
    participant User
    participant Frontend as FE
    participant BackendAPI as BE
    participant Database as DB
    participant TokenService as TS

    User->>FE: Enter credentials
    FE->>BE: POST /login
    activate BE

    BE->>DB: SELECT user by email
    alt User exists
        DB-->>BE: User record
        BE->>BE: Verify password
        alt Password valid
            BE->>TS: Generate token
            TS-->>BE: JWT token
            BE-->>FE: 200 OK {token}
            FE-->>User: Login success
        else Password invalid
            BE-->>FE: 401 Unauthorized
            FE-->>User: Invalid credentials
        end
    else User not found
        DB-->>BE: null
        BE-->>FE: 404 Not Found
        FE-->>User: User not found
    end

    deactivate BE
