# React + Inertia + Laravel — How They Work Together

This document explains how this project wires React to Laravel using Inertia, how requests flow from the browser to the backend and back (without diving into Laravel’s internal lifecycle), the app’s architecture, and how to add a new React page in this codebase.

---

## 1) How React, Inertia, and Laravel fit together

- Laravel serves a single Blade view (`resources/views/app.blade.php`) that boots the Inertia React app.
- Inertia is the bridge between client and server:
  - Client navigation and form submits happen via Inertia (no full page reloads).
  - The server returns a JSON payload (component name + props) that Inertia hydrates into the matching React page.
- File resolution is convention-based:
  - The Laravel controller/route returns a component name like `Projects/Prepare`.
  - The client resolves it to `resources/js/pages/Projects/Prepare.tsx`.

Key client files:
- `resources/js/app.tsx` — Bootstraps the SPA in the browser with:
  - `createInertiaApp({ resolve: (name) => resolvePageComponent("./pages/${name}.tsx", import.meta.glob('./pages/**/*.tsx')) })`
  - Title handling, progress bar, toast provider, and theme initialization.
- `resources/js/ssr.tsx` — Handles server-side rendering for SEO/first paint.
- `resources/views/app.blade.php` — The HTML shell that mounts Inertia and loads the current page component via Vite:
  - `@vite(['resources/js/app.tsx', "resources/js/pages/{$page['component']}.tsx"])`

What this means in practice:
- A Laravel route/controller returns `Inertia::render('Some/Page', $props)`.
- The browser receives JSON that points to `pages/Some/Page.tsx` plus props.
- Inertia swaps the current page with `Some/Page.tsx` and hydrates props — no full reload.

## 2) Request lifecycle (from React to Laravel and back)

This focuses on the Inertia request flow, not Laravel’s internal middleware/kernel.

### A. Navigating to a page (GET)
1. In React, you navigate using `<Link href="/path" />` or `router.visit('/path')` from `@inertiajs/react`.
2. Inertia issues an XHR/fetch GET to `/path`.
3. The Laravel route/controller returns `Inertia::render('Folder/Component', $props)`.
4. Inertia (client) receives JSON `{ component: 'Folder/Component', props: {…} }`.
5. The resolver maps `Folder/Component` to `resources/js/pages/Folder/Component.tsx` and renders it with props. The URL changes via history API without a full reload.

### B. Submitting data (POST/PUT/PATCH/DELETE)
1. In React, submit using `router.post('/endpoint', data)` or the `useForm` helper from `@inertiajs/react`.
2. Inertia includes the CSRF token automatically (read from `<meta name="csrf-token">`).
3. Laravel handles the request and typically responds with a redirect or `Inertia::render(...)`.
4. Inertia intercepts the response and updates the current page/props accordingly. Validation errors come back in the JSON payload and are accessible on the client.

Notes in this project:
- A global error handler in `app.tsx` catches CSRF mismatches and shows a toast.
- A progress bar is configured in `app.tsx` with color `#4B5563`.
- Theme is initialized on boot; SSR is configured for improved first paint.

## 3) Application architecture (this repo)

High-level layout of relevant pieces:

- `resources/views/app.blade.php`
  - Base HTML shell for the SPA, injects Vite bundles and mounts `@inertia`.

- `resources/js/app.tsx`
  - Browser entry: creates the Inertia app, resolves `pages/**`, sets up toasts and theme.

- `resources/js/ssr.tsx`
  - Server-side rendering entry used by Inertia SSR.

- `resources/js/pages/**`
  - React pages loaded by Inertia, e.g., `Projects/Prepare.tsx`, `landing.tsx`.
  - Page titles typically via `<Head title="..." />` from `@inertiajs/react`.

- `resources/js/layouts/**`
  - Layout wrappers. Example: `app-layout.tsx` composes `app/app-sidebar-layout.tsx`.
  - Use layouts to standardize shells (sidebar/header) around pages.

- `resources/js/components/**`
  - Reusable UI and domain components (e.g., shadcn UI, sections, diagram editors, etc.).

- `resources/js/routes/**`
  - Type-safe route helpers (generated by Wayfinder) for building URLs on the client.

- `resources/js/hooks/**`, `utils/**`, `types/**`
  - Custom hooks, helpers, and type definitions used across pages/components.

- Laravel backend
  - Routes/controllers return `Inertia::render('Folder/Component', $props)` to target a React page.
  - We do not detail Laravel’s internal lifecycle here; only its role in returning Inertia responses.

## 4) How to create a new React page in this project

You only need to do two things:

1) Add a React page file under `resources/js/pages` matching the component name you’ll return from Laravel.

Example: `resources/js/pages/Hello.tsx`

```tsx
import { Head, Link } from '@inertiajs/react';

export default function Hello() {
  return (
    <div className="p-6">
      <Head title="Hello" />
      <h1 className="text-2xl font-bold mb-4">Hello</h1>
      <p>Welcome to a new page.</p>
      <Link href="/" className="text-primary underline">Go home</Link>
    </div>
  );
}
```

Optional: wrap with your app layout

```tsx
import AppLayout from '@/layouts/app-layout';
import { Head } from '@inertiajs/react';

export default function Hello() {
  return (
    <AppLayout>
      <Head title="Hello" />
      <div className="p-6">Hello with layout</div>
    </AppLayout>
  );
}
```

2) Point a Laravel route to it and return `Inertia::render('Hello')`

In `routes/web.php` (or a feature route file):

```php
use Illuminate\Support\Facades\Route;
use Inertia\Inertia;

Route::get('/hello', function () {
    return Inertia::render('Hello', [
        'exampleProp' => 'Hi from Laravel',
    ]);
});
```

That’s it:
- Visit `/hello` — Inertia requests the route, Laravel returns JSON `{ component: 'Hello', props: { exampleProp: '...' } }`.
- The client resolves `Hello` to `resources/js/pages/Hello.tsx` and renders it.

### Tips and conventions in this repo
- Component name mapping is exact: `Inertia::render('Projects/Prepare')` -> `resources/js/pages/Projects/Prepare.tsx`.
- Use `<Head />` to set titles and meta for each page.
- For navigation:
  - `<Link href="/path">` for declarative links.
  - `router.visit('/path')` for programmatic navigation.
- For forms:
  - `router.post('/endpoint', data)` or `const form = useForm(initial)` then `form.post('/endpoint')`.
- SSR is enabled; keep pages and props serializable.

## 5) Troubleshooting
- 404 or “Component not found”: ensure the string in `Inertia::render('X/Y')` exactly matches a file at `resources/js/pages/X/Y.tsx` (default export required).
- TypeScript errors: ensure `.tsx` extension and correct imports for `@inertiajs/react`.
- Props missing on the client: confirm they’re returned from Laravel as the second arg to `Inertia::render()`.
- CSRF errors on mutations: the CSRF meta tag is in the Blade. If you submit via plain fetch, include the token; prefer Inertia’s `router`/`useForm` which handles it automatically.
